# 표준 기본틀 — DB/테이블 규칙 (v0.1)

> 신규 표준 기본틀의 테이블 설계 공통 규칙. DDL 작성·수정 시 이 규칙을 따른다.
> DB 컬럼은 snake_case 유지, Java/JS는 camelCase(자동 매핑) — [standard-template-spec.md] 참조.

## 1. 명명 규칙
- **테이블**: `t_` + snake_case, 엔티티는 단수형 (`t_user`, `t_menu`)
- **관계매핑 테이블**: `r_` + snake_case (`r_file`)
- **컬럼**: snake_case
- **PK 컬럼**: `{엔티티}_id` (`user_id`, `menu_id`, `bbs_id`)
- 커스텀 DB 타입 미사용 (yn/ymn → `varchar(1)`)
- 다국어 컬럼(`_us`/`_cn`) 미사용

## 2. PK 규칙
- **정수 대체키**: `INTEGER GENERATED BY DEFAULT AS IDENTITY` (SQL 표준, 시퀀스 자동생성 → 로컬 바로 실행)
- **자연키**: 의미있는 문자열은 그대로 (`user_id` varchar, `code_id`, `authgrp_id`, `bbsinfo_cd`)
- **복합키**: 순수 매핑 테이블 (`t_auth_user` = user_id+authgrp_id, `r_file` = map_key+file_id)

## 3. FK(참조) 컬럼 규칙  ★핵심
- **참조 컬럼명 = 참조 대상 테이블의 PK 컬럼명을 그대로 사용**
  - 예: `t_user.user_id` 참조 → 어느 테이블에서든 **`user_id`** (기존 `user_tcd` 폐기)
  - `t_bbsinfo.bbsinfo_id` 참조 → `bbsinfo_id` (기존 `bbsinfo_tcd` 폐기)
  - `t_prog.prog_id` 참조 → `prog_id` (기존 `prog_tcd` 폐기)
- **자기참조**: `p_` 접두사 (`p_menu_id`, `p_code_id`, `p_bbs_id`)
- **같은 대상을 한 테이블에서 여러 번 참조할 때 세부 규칙**:
  - 유형이 하나: 참조PK명 그대로 — `file_id`
  - 같은 유형이 여러 건: 참조PK명 + 순번 — `file_id1`, `file_id2`, `file_id3` (예: t_config 로고 3개)
  - 서로 다른 유형을 구분해야 하면: `{유형}_` 접두 — `logo_file_id`, `thumbnail_file_id`, `banner_file_id`
  - 여러 유형 + 각 유형도 여러 건: `{유형}_file_id1` — `logo_file_id1`, `logo_file_id2`
  - **요약**: 유형이 여럿이면 앞에 구분명칭, 같은 유형이 여럿이면 뒤에 숫자. 실제 용도는 `COMMENT`에 명시.
- **다형적 참조**(여러 테이블 중 하나를 가리킴): 범용명 유지 + 구분컬럼
  - `t_auth.conn_id`(+auth_gbn), `t_menu.conn_id`(+conn_ty), `r_file.map_key`(+file_loc)
- **물리 FK 제약(FOREIGN KEY)은 걸지 않는다.** 논리적 참조만 두고 무결성은 애플리케이션에서 관리(성능·유연성·MyBatis 관례).

## 4. 공통 audit 컬럼 (전 테이블 필수)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| reg_id | varchar(30) | 등록자 |
| reg_dt | timestamp | 등록일시 |
| reg_ip | varchar(45) | 등록 IP (IPv6 대비) |
| upd_id | varchar(30) | 수정자 |
| upd_dt | timestamp | 수정일시 |
| upd_ip | varchar(45) | 수정 IP |
- 로그성 테이블(`t_event_log` 등)은 `reg_*`만.

## 5. 논리 삭제
- `use_yn varchar(1) DEFAULT 'Y'`. 삭제는 `use_yn = 'N'` (물리삭제 지양).

## 5-1. 날짜/시간 포맷 (통일)
- **시스템 자동기록 일시**(`reg_dt`/`upd_dt`/`last_login_dt` 등): `timestamp` 타입, 서버가 `NOW()`로 기록.
- **사용자 입력 날짜(날짜만)**: `varchar(10)`에 `YYYY-MM-DD` 문자열로 저장 (예: `t_user.birth`, `t_popup.start_dt/end_dt`, `t_bbs.*_dt`).
- **사용자 입력 날짜+시간**: `varchar(19)`에 `YYYY-MM-DD HH:mm:ss` 문자열로 저장.
- 프론트는 텍스트 직접입력 대신 공통 `DateField`(AntD DatePicker + dayjs) 사용 — Form에는 위 문자열 포맷으로 바인딩.

## 6. Y/N 플래그
- `varchar(1)`, 컬럼명 **`_yn`** 접미사로 통일 (기존 `_at` → `_yn`).
- DEFAULT `'Y'` 또는 `'N'` 명시.

## 7. 코드성 값
- 공통코드(`t_code`) 참조, 컬럼명 `{용도}_cd` (`mem_cd`, `gen_cd`, `status_cd`, `type_cd`).

## 8. 정렬 / 계층
- 정렬순서: `ordr integer`
- 계층구조: `p_{pk}` 자기참조 (`p_menu_id`, `p_code_id`)

## 9. 표준 데이터타입
| 용도 | 타입 |
|---|---|
| 계정/코드 ID | varchar(30) 이하 |
| 명칭·제목 | varchar(255) |
| 장문·HTML | text |
| 날짜일시 | timestamp (문자열 날짜 지양) |
| 여부(Y/N) | varchar(1) |
| IP | varchar(45) |

## 10. 컬럼 순서
- **공통컬럼은 항상 테이블 맨 뒤**에, 다음 순서로 고정:
  `use_yn` → `reg_id` → `upd_id` → `reg_dt` → `upd_dt` → `reg_ip` → `upd_ip`
- 업무/데이터 컬럼을 앞에, 공통컬럼을 뒤에 두어 가독성 확보. (로그성 테이블은 reg_* 만)

## 11. SQL 표기
- **SQL 예약어는 대문자**: `CREATE TABLE`, `NOT NULL`, `DEFAULT`, `PRIMARY KEY`, `CONSTRAINT`, `UNIQUE`, `COMMENT ON`, `IS`, `GENERATED BY DEFAULT AS IDENTITY`
- **타입명도 대문자**: `VARCHAR`, `TIMESTAMP`, `INTEGER`, `TEXT`, `BOOLEAN`
- **식별자(테이블/컬럼)만 소문자**

## 12. 기타
- 전 컬럼 `COMMENT ON` 주석 필수.
- 스키마 변경 시 `sql/schema.sql`을 단일 소스로 최신화(수동 실행).
